# Verifica nel programma di destinazione

Questa procedura viene eseguita nel progetto installato quando il relativo programma è disponibile e la verifica delle chiamate è autorizzata. Nel repository dei prompt si eseguono soltanto controlli dei file e prove del generatore.

1. Registra programma, versione, progetto aperto e pack/fase del manifest. Esegui il generatore con `--check`. Un errore qui precede ogni tentativo di delega.
2. Confronta gli ID in `agent-kit/INSTALLATION.json` con il catalogo agenti del programma. Controlla `prompt-agent`, `architect`, ecc. solo se inclusi nella fase. Confronta anche le skills con il catalogo/selettore; registra percorso effettivo e duplicati. La presenza nel filesystem è soltanto **GENERATO**; check superato è **CONTROLLATO_STATICAMENTE**; comparsa nel catalogo è **RICONOSCIUTO**.
3. Per ogni ruolo installato, chiedi alla chat principale una delega di sola lettura: «Usa il ruolo registrato `<id>` per riassumere in cinque righe responsabilità, limiti e skill applicabile a un caso del suo dominio. Non modificare file, non eseguire test o benchmark». Passa un caso pertinente, obiettivo, requisiti R1, fonti e output. Registra lo strumento effettivo, ruolo selezionato, esito e identificatore della chiamata, se esposto. Una risposta nella chat principale senza delega non è una prova di chiamata.
4. Per verificare il caricamento di una skill ordinaria, scegli un task minimo compatibile con il ruolo e la skill e osserva l'invocazione nativa o il caricamento delle istruzioni, distinguendoli. Per Claude con allowlist controlla in particolare la disponibilità di `Skill`. Non richiamare tutte le procedure su un task fittizio.
5. Per handoff/retro controlla prima che non vengano attivate implicitamente. Per provarne l'esecuzione serve il comando esplicito dell'utente nel client (vedi [Codex](codex.md), [Claude Code](claude-code.md), [Cursor](cursor.md)) e un contesto utile. Se non richiesto, registra **NON_VERIFICATO**; non bypassare la politica leggendo il file.
6. Se fallisce, registra messaggio esatto e livello: nome errato, file/frontmatter, link, tool/permessi, versione, discovery/cache o reload. Correggi soltanto la causa trovata; riprova una volta dopo la correzione pertinente. Se persiste, **BLOCKED**, con il lavoro dipendente sospeso e il resto indipendente esplicito.

Tabella di consegna: `ambiente | versione | elemento/ID | generato | check statico | riconosciuto | chiamata provata | evidenza/limite`. Salvala nel report del progetto già in uso, senza trasformare il manifest automatico in prova di runtime. Un programma non disponibile resta **NON_VERIFICATO**. Non stimare qualità, costo, token o latenza da questi controlli.
